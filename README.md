# CodeNarrator — Python Tracebacks Explained by an LSTM Encoder–Decoder

**CodeNarrator** reads a Python error or traceback and **generates one short English sentence** that explains it, word by word, with a neural network **trained from scratch**.

It compares two sequence-to-sequence models written in **PyTorch** — a **BiLSTM encoder–decoder baseline** and the same model with **Bahdanau attention** — and ships the best one in a **React + FastAPI** web app.

> **No Transformers. No pretrained model. No LLM API. No lookup table of explanations.**
> Every sentence is generated by the saved LSTM.

## Overview

A Python traceback tells you *where* something failed, but not always *why* in plain words.
CodeNarrator turns a traceback into a single readable sentence, and the project studies a precise question:

> **Does Bahdanau attention help a BiLSTM encoder–decoder explain tracebacks, and where does it still fail?**

The repository contains the full pipeline: dataset, preprocessing, models, training, evaluation, an executed notebook, a REST API and a web interface.

---

## Key Features

- **Two models, fairly compared** — BiLSTM encoder + LSTM decoder (baseline) vs. the same model with Bahdanau additive attention
- **Copy slots** — unknown words of the error message (a new file or column name) are replaced by `<S1>`, `<S2>`… in the input and restored in the output
- **Header adapter** — bare one-line errors are wrapped in the standard `Traceback (most recent call last):` header
- **Three kinds of test sets** — familiar families, novel identifiers, and **unseen families** (zero-shot)
- **Honest metrics** — ROUGE-1/2/L, BLEU-4, exact match, entity recall (own implementations cross-checked against `rouge-score` and NLTK)
- **Multi-seed evaluation** — 3 seeds, two training budgets, mean ± standard deviation
- **Web app** — React + Tailwind interface, FastAPI backend, attention highlights, reliability warnings, ~30 ms per request on CPU
- **Test suite** — unit, API and notebook/app consistency tests

## Model Architecture

```text
Baseline                                  + Bahdanau attention

traceback tokens                          traceback tokens
      ↓                                         ↓
  Embedding (128)                          Embedding (128)
      ↓                                         ↓
 BiLSTM encoder (2 × 256)                 BiLSTM encoder (2 × 256)
      ↓                                         ↓  all encoder states
 final state → bridge                      final state → bridge
      ↓                                         ↓
 LSTM decoder (256)  ←  one fixed vector   LSTM decoder (256)  ←  context vector
      ↓                                         ↑ masked softmax over all
 Linear + softmax → next word               encoder positions, at every step
                                                ↓
                                           Linear + softmax → next word
```

| | Baseline | + Attention |
|---|---:|---:|
| Parameters | 1.86 M | 2.80 M |
| Training | teacher forcing | teacher forcing |
| Decoding | greedy | greedy |
| Early stopping | validation loss | validation loss |

Hyper-parameters (`DEFAULT_CONFIG` in `src/train.py`): embedding 128, hidden 256 per direction, dropout 0.3, Adam 1e-3, batch 64, gradient clipping 1.0, seeds 42 / 43 / 44.

## Dataset

The dataset is **synthetic** (rule-generated) and lives in `academic/dataset/`:

| File | Examples | Purpose |
|---|---:|---|
| `train.csv` | 8,320 | Training (104 error families) |
| `validation.csv` | 1,560 | Early stopping, checkpoint selection |
| `test.csv` | 1,560 | Familiar families |
| `test_novel_entities.csv` | 832 | Same families, new file / column / variable names |
| `test_unseen_families.csv` | 880 | 11 families never seen in training (zero-shot) |

`build_dataset.py` regenerates the data deterministically.

> **Important:** the data is formulaic and synthetic. High scores on familiar families partly measure template learning. No claim of real-world reliability is made.

## Results

Real numbers, mean ± std over 3 seeds. **Protocol A** = 30 epochs, patience 5. **Protocol B** = 60 epochs, patience 12 (budget-matched control).

| Test set | Protocol | Baseline ROUGE-L | Attention ROUGE-L | Baseline exact match | Attention exact match |
|---|---|---:|---:|---:|---:|
| Familiar families | A | 71.8 ± 40.4 | **99.8 ± 0.0** | 45.6 ± 39.5 | **98.9 ± 0.0** |
| Familiar families | B | 96.5 ± 0.8 | **99.8 ± 0.0** | 74.3 ± 5.0 | **98.9 ± 0.0** |
| Novel identifiers | A | 73.3 ± 40.6 | **99.6 ± 0.0** | 52.3 ± 44.7 | **95.4 ± 0.2** |
| Novel identifiers | B | 97.5 ± 0.2 | **99.7 ± 0.0** | 83.3 ± 2.4 | **96.3 ± 0.7** |
| Unseen families | A | 24.2 ± 3.7 | **33.8 ± 4.2** | 0.0 | 0.0 |
| Unseen families | B | 24.5 ± 1.1 | **35.7 ± 3.0** | 0.0 | 0.0 |

All metrics (ROUGE-1/2/L, BLEU-4, exact match, entity recall) are in [`results/results_tables.md`](results/results_tables.md).

Main findings:

- **Attention wins everywhere**, most clearly on exact match and on unseen families.
- In protocol A, one baseline seed (43) stopped on a **loss plateau** and produced one sentence for every input, hence the huge standard deviation. With the larger budget (B) all baseline seeds converge, but remain below attention.
- Attention reaches its best validation loss in about 25–55 epochs and never shows the plateau.
- **Both models fail on unseen families** (exact match 0): they output a fluent sentence about a different error.

---

## Limitations

- **Synthetic, formulaic data** — no evaluation on real tracebacks.
- **Unseen error families and exception classes** get a fluent but wrong sentence (e.g. `PaymentError: card declined`). The web app warns when the exception class was never seen in training.
- **Copy slots only help words unknown to the source vocabulary.** Hyphenated names and dotted module paths are only partly reproduced.
- **Chained tracebacks** ("During handling of the above exception…") were never seen in training.
- On 28 hand-written real inputs: **17 correct, 3 partial, 8 incorrect** (see [`results/inference_examples.csv`](results/inference_examples.csv)).

- **Evaluation:** own ROUGE / BLEU, cross-checked with `rouge-score` and NLTK
- **Notebook:** Jupyter (`ipykernel`, `nbformat`, `nbclient`)

---

## Training vs Inference

- **Training** happens once, offline (`tools/train_models.py` or the notebook with `FORCE_RETRAIN = True`). It produces the `.pt` files in `checkpoints/`.
- **Inference** (notebook, `src/inference.py`, the web app) only **loads** `checkpoints/codenarrator_best.pt` and runs greedy decoding. **The web app never trains and needs no GPU.**
- `codenarrator_best.pt` was chosen on **validation** data only, never on a test set.

# Installation (Windows PowerShell)

## 1. Clone and install

```powershell
git clone https://github.com/Siwar-Ben-Mustapha/CodeNarrator.git
cd CodeNarrator
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> `pyzmq>=26` matters on Windows: with older versions `import torch` fails inside Jupyter kernels with *WinError 1114*.

## 2. Run the web app

Build the React app once, then start a single server that also serves the interface:

```powershell
cd webapp\frontend
npm install
npm run build
cd ..\..
python -m uvicorn webapp.backend.main:app --host 127.0.0.1 --port 8000
```

Open **http://127.0.0.1:8000**

Development mode with hot reload (two terminals):

```powershell
python -m uvicorn webapp.backend.main:app --port 8000
cd webapp\frontend; npm run dev          # http://localhost:5173 (proxies /api to port 8000)
```

## 3. Use the model from Python

```python
import sys; sys.path.insert(0, "src")
from inference import Summarizer

s = Summarizer("checkpoints/codenarrator_best.pt")      # CPU, evaluation mode
print(s("sqlite3.IntegrityError: UNIQUE constraint failed: users.email"))
print(s.warnings("PaymentError: card declined"))        # reasons why the output may be unreliable
```

Or from the command line:

```powershell
python src/inference.py checkpoints/codenarrator_best.pt my_traceback.txt
```

## 4. Run the notebook

Open `academic/CodeNarrator_Final.ipynb` in VS Code (Python kernel from the venv) and **Run All**. It loads the CSVs in `academic/dataset/` and the checkpoints in `checkpoints/` (relative paths, no Google Drive). Takes about 3 minutes on CPU.

A missing checkpoint is trained from scratch. `FORCE_RETRAIN = True` retrains everything into `checkpoints/notebook_retrain/` without touching existing files.

## API

```text
GET  /api/health
POST /api/summarize     {"traceback": "..."}
```

Response fields: `summary`, `warnings`, `latency_ms`, `source_tokens`, `attention`, `n_unk`, `truncated`.

| Status | Meaning |
|---|---|
| `200` | Summary generated |
| `422` | Empty or invalid input |
| `413` | Input over 20,000 characters |
| `503` | Checkpoint missing or incompatible (the message says why) |

Environment variables: `CODENARRATOR_CHECKPOINT`, `CODENARRATOR_DEVICE`.

## Tests and Evaluation

```powershell
python tests/run_all.py                                                       # 7 test files, ~6 min on CPU
python tools/evaluate_checkpoints.py                                          # protocol A  -> results/main_run
python tools/evaluate_checkpoints.py --ckpt checkpoints/budget60 --out results/budget60   # protocol B
python tools/train_models.py --tag my_run --epochs 30 --patience 5            # optional retraining, never overwrites
```

The tests cover tokenisation, ROUGE/BLEU (checked against `rouge-score` and NLTK), copy slots, tensor shapes, padding masks, teacher forcing, loss masking, checkpoint round-trips, determinism, the FastAPI endpoints and error handling, and **consistency**: the batched evaluation pipeline, single-request inference, the FastAPI endpoint and the code pasted in the notebook all give the same output.
